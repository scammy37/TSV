Maintenance requests that don't get lost.

A ticket and work-order system for apartment complexes. Homeowners submit service requests and follow them to resolution. Management triages, assigns and closes them against SLA targets — with an audit trail behind every change.

Try the live demo View source

React · Node/Express · PostgreSQL — runs as a single service on one port.

Two portals, one ticket

Residents and staff see the same request from different sides. What management writes internally stays internal.

Homeowner

Submit it and watch it move

  • File a request with category, priority and location
  • Track status live, with the SLA target date in view
  • Comment back and forth with management
  • Correct the details while the ticket is still open
  • Read the full history of everything that happened
  • Get emailed on submission, status change, reply and resolution
Management

Triage, assign, and prove it

  • One queue, with quick views for unassigned, mine and overdue
  • Filter by status, priority, category and assignee, plus free-text search
  • Assign to staff — each person's open workload shows in the picker
  • Change priority, which recalculates the SLA deadline
  • Leave internal notes the homeowner never sees
  • Promote, demote and deactivate accounts from the people directory

Built to be trusted with resident data

The parts that are easy to skip, and expensive to skip.

Roles enforced in the API

Homeowner, staff and management are checked server-side, not hidden in the UI. A homeowner sees only their own requests.

Append-only activity log

Every ticket carries a complete history. Status moves follow enforced transitions, so the trail can't contain nonsense.

SLA deadlines by priority

Measured from when the ticket was filed. Reports cover compliance, average resolution and first-response time.

Safe password reset

Single-use hashed tokens that expire in an hour. Deactivating an account invalidates its JWT immediately.

Email you can audit

Every notification is recorded in email_logs — sent, failed or skipped — so silent delivery failures are visible.

Tested against real Postgres

The integration suite runs on an actual PostgreSQL database in CI, on Node 20 and 22, not against mocks.

Try it without installing anything

A GitHub Codespace builds the whole thing — database, demo data and all — in a couple of minutes.

  1. On the repo, click Code → Codespaces → Create codespace on this branch.
  2. Wait for it to build. It starts PostgreSQL, applies the schema, loads demo data and builds the frontend.
  3. In the Ports tab, click the globe icon next to port 5000.
  4. Sign in with any account below — the password is Password123!

What it's made of

The API serves the built frontend, so deployment is one process, one port and one origin — no CORS setup, no separate static host. Anywhere that provides a DATABASE_URL will run it.
